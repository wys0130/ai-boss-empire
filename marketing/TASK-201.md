## 一、任务背景与战略意图

当前平台已具备面向企业客户的标准结算能力，但针对国内规模庞大的**网络经营个体户**（电商、直播、知识付费、灵活用工）存在合规接入盲区。  
本次升级核心目标：**打通个体户执照（网络经营）与对公账户参数体系**，实现“执照即主体、对公即通道”的国内正规军结算闭环。

---

## 二、升级范围定义

### 1. 主体识别层（新增）
- 支持 **“网络经营个体户”** 营业执照类型识别（含“仅限互联网销售”等经营范围限定词）。
- 自动提取关键字段：  
  `统一社会信用代码` / `经营者姓名` / `经营范围` / `网络经营地址（店铺链接或平台ID）`。

### 2. 对公参数体系（重构）
- 新增 **对公账户参数包**（BankProfile），包含：
  - 开户行联行号（12位）
  - 对公账号（16-23位）
  - 账户名称（必须与执照经营者姓名一致）
  - 税务登记类型（默认“小规模纳税人”）
  - 结算周期（T+1 / T+7 可选）

### 3. 合规校验规则（强化）
- 强制校验：`执照经营者姓名` == `对公账户名称`（支持“个体工商户”字号前缀容错）。
- 强制校验：`经营范围` 包含“网络经营”或“互联网销售”关键词。
- 预警校验：若对公账户开户名含“有限公司”字样，则触发“主体类型不匹配”拦截。

## 三、系统参数配置（技术侧）

```yaml
# 接入参数示例（内部配置模板）
individual_business:
  enabled: true
  license_type: "网络经营个体户"
  required_fields:
    - unified_credit_code
    - operator_name
    - business_scope
    - network_platform_id
  bank_profile:
    required: true
    fields:
      - bank_code          # 联行号
      - account_no         # 对公账号
      - account_name       # 账户名称
      - tax_type           # 默认: small_scale
    validation:
      name_match: true
      scope_keyword: ["网络经营", "互联网销售"]
      block_company_suffix: true
```

## 四、业务流变更说明

**原流程：**  
企业客户 → 企业执照 → 对公账户 → 结算

**升级后流程：**  
网络经营个体户 → 个体户执照（网络经营） → 对公账户（同名） → 合规校验 → 结算

> 注：若个体户无对公账户，可引导至合作银行“个体工商户便捷开户”通道（后续单独立项）。

## 五、跨部门协同分工

| 部门 | 职责 |
|------|------|
| 合规部 | 确认执照经营范围表述与各地市场监管局差异，输出《网络经营个体户合规白名单》 |
| 财务部 | 更新对公账户入账凭证模板，增加“个体户-网络经营”专用备注字段 |
| 技术架构组 | 完成参数包上线，并保证与现有企业结算模块并行不冲突 |
| 客服中心 | 准备FAQ：个体户无对公账户、执照经营范围不含“网络经营”等场景话术 |

---

## 六、验收标准

1. 使用真实“网络经营个体户”执照样本，可成功创建结算主体。
2. 对公账户名称与经营者姓名不一致时，系统100%拦截。
3. 经营范围不含“网络经营”关键词时，系统提示“暂不支持该主体类型”。
4. 全流程（提交-校验-绑定-结算）响应时间 < 2秒。

---

## 七、风险提示

- 部分省市对“网络经营个体户”执照发放口径不一，需与属地监管保持同步。
- 对公账户开户审核周期较长，建议在用户引导流程中增加“预审”环节。
