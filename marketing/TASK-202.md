## 一、任务背景与目标

前期依赖第三方众筹/打赏通道（爱发电）作为境内收款兜底，存在以下不可控风险：

- 平台政策波动导致资金冻结或通道下架；
- 结算周期长（T+7 ~ T+15），影响现金流；
- 无法自定义订单备注、回调验签、分账逻辑；
- 用户跳转体验割裂，跳出率高。

**本次任务目标：**  
构建一套**境内专属隔离收银台**，实现：

1. 完全自主可控的支付路由（微信/支付宝/银联聚合）；
2. 与主站业务系统（订单、会员、发票）物理隔离；
3. 支持动态费率、分账、退款、对账；
4. 前端 UI 与品牌一致，无第三方跳转感。

## 三、核心模块交付说明

### 3.1 支付路由（Payment Router）

- **动态路由策略：** 根据用户设备（H5/小程序/PC）、金额、风控标签，自动选择最优渠道；
- **降级机制：** 当主渠道故障或超时（>3s），自动切换备用渠道，用户无感知；
- **幂等控制：** 同一订单号仅允许一次成功支付，重复回调自动丢弃。

### 3.2 订单快照（Order Snapshot）

- 收银台内部独立建单，与主站订单通过 `out_trade_no` 关联；
- 快照字段：商品摘要（脱敏）、金额（分）、优惠明细、过期时间（默认15分钟）；
- 快照数据保留 180 天，支持审计导出。

### 3.3 对账引擎（Reconciliation）

- 每日凌晨自动拉取渠道账单（微信/支付宝/银联），与本地流水逐笔比对；
- 差异处理：长款（渠道有、本地无）自动挂起并告警；短款（本地有、渠道无）触发补单或退款；
- 生成对账报告（PDF/CSV），推送至财务组。

### 3.4 分账与退款

- **分账：** 支持按比例或固定金额分给多个收款方（如平台、渠道商、税筹账户）；
- **退款：** 支持原路退回，部分/全额，退款状态实时同步至主站；
- **防重：** 退款请求需携带 `refund_no`，同一退款号只处理一次。

### 3.5 风控闸门（Risk Gate）

- 规则引擎：单笔限额、单日累计、频次、黑名单（手机号/设备指纹/IP）；
- 实时拦截：命中规则直接拒绝并记录原因，不进入支付渠道；
- 人工审核队列：高风险订单进入待审列表，支持后台人工放行/驳回。

## 四、安全与合规

| 项目 | 实现方案 |
|------|----------|
| 传输加密 | HTTPS + 国密SM2/SM4（境内合规要求） |
| 签名机制 | 内部API请求使用 HMAC-SHA256 + 时间戳防重放 |
| 数据隔离 | 收银台数据库独立于主站，仅通过API交互 |
| 密钥管理 | 硬件加密机（HSM）存储商户私钥，定期轮换 |
| 合规备案 | 已对接持牌机构，支付路由不触碰资金池 |

## 七、应急预案

- **渠道故障：** 路由自动降级，若全部渠道不可用，收银台返回“系统繁忙”并推送告警至值班群；
- **资金差异：** 对账引擎发现长款/短款，2小时内人工介入，冻结相关订单；
- **安全事件：** 若检测到批量盗刷特征，风控闸门自动全量拦截，并触发熔断开关。
